# 数字孪生项目面试定位手册

> 配套工程：`DT/`（220kV 智能变电站 3D 数字孪生 Demo）
> 用途：面试中"提到这一部分"时，用一句话定位 + 可验证证据 + 30/60/90 天承诺，把 Demo 变成"我上手就能接管哪一块"的证明。

---

## 0. 先背这一句（三段式定位句）

> "在数字孪生项目里我的位置是**表现层与工业数据层之间的那一层**：把一次设备的 3D 模型、实时测点和遥控指令串成可视闭环。我做过一个 220kV 变电站的 Demo，**前端 Three.js + Vue 3 大屏（约 3200 行）、后端 FastAPI + OPC UA + MQTT + WebSocket（约 1150 行）全是我自己打通的**，倒闸遥控可以从网页点下去、写到 OPC UA 可写节点、再由 WebSocket 推回 3D 场景让电流粒子停下来。所以进项目后我第一天能接的是**场景与数据绑定 + 大屏联调**这块，不需要从零熟悉。"

为什么这句有效：它同时回答了三个面试官真正关心的问题——**你是谁、你凭什么、你来了接谁的活**。

| **机理模型层** | IEC 60076-7 一阶热路模型（油温/绕组热点由负载率与冷却能力演化）+ 拓扑潮流（`I=S/(√3·U)`、失电即零流） | 这是"数字孪生"与"3D 大屏"的分界线：数据是**算出来的**，不是填进去的 |
| **测试** | 51 个用例（标准库 unittest，无需 pytest）：功率守恒、电流导出关系、热路解析解与稳定性、保护跳闸、SF6 闭锁、告警边沿触发 | 物理约束被测试锁死，不是"看着像对" |
| 闭环联动 | 网页 → `POST /api/control/breaker` → 写 OPC UA 节点 → MQTT 发布 → WS 广播 → 3D 粒子流停止 | **双向孪生**（能下发控制 + 状态回写），这是区别于"3D 大屏"的关键 |
| 可靠性设计 | 后端离线时本地仿真 tick 自动接管，Header 显示"本地离线模式" | 有降级意识，演示不崩，工程感强 |
| 交付形态 | `npm run build` 产物已生成（JS 1.83 MB / CSS 25 KB），零外部模型资产、秒开 | 可直接现场演示，不依赖网络与美术资源 |

**一句话提炼**：这不是"一个 3D 页面"，而是**一条从工业协议到 WebGL 的完整数据通路**，你正好站在这条通路的关节上。

## 1.5 最有说服力的一段经历（面试直接讲这一段）

改造前的 Demo 里有一个**物理矛盾**：`gis-201` 进线电流是 472.4A，而两台主变电流 546.2 + 521.0 = 1067.2A。
单电源终端站里，进线电流不可能只有主变电流之和的 44%；而且**断路器分闸之后，全站负荷纹丝不动、主变温度也不变**。

我做的第一件事不是加特效，而是把数据层重建为"物模型 + 机理模型"驱动：

1. 把测点、告警阈值、OPC UA 映射、物理参数全部搬进 `device_model.json`，代码里不再硬编码点位；
2. 用 **IEC 60076-7 一阶热路模型**算油温与绕组热点温度，用**拓扑潮流**算电流（`I = S/(√3·U)`）；
3. 故障注入从"给温度赋值"改成"改边界条件"——主变过热 = 冷却器全停，SF6 泄漏 = 气压衰减，出线过载 = 负荷激增后由保护延时跳闸；
4. 补 51 个测试，把"功率守恒、失电即零流、负荷转移"这些物理约束钉死。

改完之后：分闸 202 母联，trans-2 退出、其负荷**转移**给 trans-1，负载率 76.1% → **151.9%**；
注入主变过热，油温按一阶惯性从 **58.2℃ 爬到 91.3℃**，第 31 步越过 85℃ 才告警。
**这段经历的价值在于它证明我能发现物理层面的矛盾，而不只是会写前端和特效。**

## 2. 定位坐标系：大型数字孪生项目通常这样切人

| 角色 | 干什么 | 你的当前匹配度 |
| :--- | :--- | :--- |
| A. 三维资产/TA 管线 | Blender/Revit → 轻量化 → glTF，PBR、动画、LOD、Draw Call | 40%：会调 Blender 导出与 glTF 加载，没做过 CAD 减面流水线 |
| B. 3D 可视化前端/引擎 | Three.js/Babylon/Cesium/UE 场景框架、相机调度、拾取、后处理、性能调优、大屏适配 | **85%：这是你的主战场，Demo 证据最厚** |
| C. 工业数据接入（IIoT） | OPC UA / Modbus / IEC 104 / MQTT / Kafka、点位建模、时序库、边缘网关 | 60%：自建过 OPC UA 服务端与 MQTT 网关、WS 推流；缺真实设备侧与边缘经验 |
| D. 平台/中台架构 | 微服务、物模型、规则引擎、告警引擎、GIS/BIM 集成、权限 | 35%：有数据模型与接口分层意识，无中台与多租户经验 |
| E. 业务应用/解决方案 | 倒闸操作票、巡检、故障预案、能效、场景编排、售前交付 | 55%：Demo 里把倒闸、故障注入、预案弹窗的业务流跑通了 |
| F. 数据智能/AI | 预测性维护、健康度评估、异常检测、视频 AI | 20%：有健康度雷达图与评分字段，未做算法 |

**结论**：你的支点是 **B（可视化前端/引擎）**，杠杆是 **B×C 的交集**——"能把工业数据接到 3D 场景里的人"。这个交集天然稀缺：纯前端不懂 OPC UA 与点位模型，纯后端不懂 WebGL 性能与交互，美术不懂协议。**这就是你的定位，不需要跟任何人抢。**

## 3. 怎么"找到"定位：三环交集法（可直接套用到任何大项目）

定位不是"我想做什么"，而是下面三者的交集：

1. **项目最痛的环节**：大项目里 3D 性能（帧率/Draw Call/大屏分辨率）与数据接入（点位海量、协议杂）通常是瓶颈，而不是建模。
2. **我有证据的能力**：见第 1 节表格——B 最厚，C 有一半。
3. **组织缺谁**：看 JD 与团队构成，缺的是"能独立把 3D 场景和实时数据跑通的人"，还是一颗螺丝钉。

### 面试前的 3 个动作

- **拆 JD 权重**：把 JD 里的关键词映射到第 2 节的 A–F，看它其实在招哪个角色。写"Three.js/Cesium 性能优化"→ 招 B；写"OPC UA/Modbus/时序数据库"→ 招 C；写"数字孪生平台/物模型/微服务"→ 招 D。**不要用一套说辞打所有 JD**。
- **问团队现状**（面试时反问，同时完成定位）：现在场景是美术资产还是程序化？点位有多少个、谁维护物模型？帧率预算和验收标准是什么？有没有真实设备接入还是先做模拟器？—— 这几个问题的答案直接告诉你进去接哪一块。
- **准备"入职 30 天交付物"**：定位最强的表达不是"我会什么"，而是"我第一个月能替你解决什么"。

## 4. 三条可选定位路线（按目标岗位选一条主推，不要三条都说）

### 路线 1：3D 可视化前端 / 数字孪生前端（最稳，证据最厚）
- 主打：Three.js 场景框架、自定义 Shader、后处理与性能、Vue 大屏与 ECharts、场景与 UI 双向联动。
- 要补的缺口：**性能量化能力**（帧率、Draw Call、GPU 时间、实例化与合批、LOD）、大屏分辨率适配、Cesium/GIS 或 UE 其中一项。
- 30/60/90：30 天接场景框架与交互层；60 天立性能预算与压测基线（目标 60fps @ 2K/4K）；90 天独立负责一个站的场景交付。

### 路线 2：数字孪生应用/全栈（适合乙方交付型、中小团队）
- 主打：**端到端闭环**——协议接入 + 后端接口 + 实时推流 + 3D 表现，能一个人把 Demo 变成可交付原型。你已经有这个能力。
- 要补的缺口：真实时序库（TDengine/InfluxDB/ClickHouse）、鉴权与多租户、容器化部署、CI。
- 30/60/90：30 天把硬编码点位改成**配置化物模型**；60 天接入真实数据源（模拟器/网关）替换仿真；90 天独立交付一个客户场景。

### 路线 3：工业数据接入 / 平台（天花板最高，转型成本最大）
- 主打：OPC UA 地址空间与订阅、MQTT 主题设计、点位建模、时序存储与数据治理。
- 要补的缺口：Modbus / IEC 60870-5-104 / IEC 61850（变电站必备！）、边缘网关、Kafka、设备接入并发与断线续传。
- 30/60/90：30 天摸清现有点位表与协议清单；60 天独立接一类新协议设备；90 天负责一个站的接入质量与告警收敛。

> 提示：如果目标是电网/能源行业，**IEC 61850** 是变电站数字孪生的硬通货，你 Demo 里已经有了 OPC UA 与"一次设备/倒闸/操作票"的语境，补 61850 的叙事成本很低，收益极高。

## 5. 面试 3 分钟讲法（照这个顺序说，别从技术栈开始念）

1. **业务背景（15 秒）**：220kV 智能变电站，数字孪生大屏要解决三件事——**看得见**（三维设备）、**看得懂**（实时遥测与告警）、**控得动**（遥控倒闸仿真）。
2. **我的位置（15 秒）**：我负责可视化前端与数据通路，即第 0 节那句话。
3. **技术亮点，讲判断而不是讲功能（90 秒）**：
   - *程序化建模 vs 美术资产*：为了零资产、秒开、可离线，主变/GIS/门架用 Three.js 程序化几何构建；同时保留 `GLTFLoader` 通道，需要高保真时可直接换 Blender 导出的 `.glb`。**这是"看交付场景选方案"的判断。**
   - *数据驱动渲染*：全局响应式 store 作单一数据源，驱动指示灯、电流粒子流、热力图着色器、告警脉冲环；场景与 UI 通过 Raycaster 拾取 + TWEEN 运镜双向联动。
   - *双向闭环（重点说）*：遥控分闸 → `POST /api/control/breaker` → 后端写入 OPC UA 可写节点 `BreakerPosition` → MQTT 发布变位报文 → WebSocket 广播 → 3D 电流粒子流即时停止 + 操作票落库。**能做到"控制回写"才算数字孪生，只做可视化那叫大屏。**
   - *数据是算出来的（最硬的一条）*：油温由 IEC 60076-7 一阶热路模型根据负载率与冷却能力演化；全站电流由拓扑潮流按 `I=S/(√3·U)` 导出。所以分闸会真的改变电流、负载率、温度和健康度；热力图着色依据的是模型算出的真实温度，而不是位置启发式。
   - *降级设计*：后端离线时本地仿真 tick 自动接管，界面明确提示"本地离线模式"，演示永不黑屏。
4. **难点与取舍（30 秒）**：UnrealBloom + 粒子在 4K 下吃 GPU，取舍是降低 Bloom 分辨率并给粒子做上限；时序数据用 SQLite 是 Demo 权宜，真实项目要换 TDengine/InfluxDB；点位目前硬编码，下一步做成配置化物模型。
5. **结果 + 下一步（15 秒）**：构建产物 1.8 MB 可直接现场演示，全链路闭环可复现；我知道它离生产还差鉴权、时序库、点位配置化与压测基线，这正是我入职后要补的。

## 6. 高频追问与答法（提前想好，答不上会掉档）

| 会被问 | 怎么答 |
| :--- | :--- |
| 为什么不用 Unity/UE？ | 交付形态决定：Web 端免安装、可并发查看、与业务系统同栈、迭代与运维成本低；UE 更适合高保真离线大屏/VR。**选型看约束，不看引擎强弱。** |
| 数字孪生和 3D 可视化大屏的区别？ | 孪生是**双向且同步**：模型与物理实体一一映射、数据实时驱动、指令可反向下发并回写状态。我的 Demo 里遥控写 OPC UA 节点再回推场景就是这条线。 |
| 性能怎么保证？ | 讲量化：目标帧率与分辨率 → Draw Call 与三角面预算 → 实例化/合批（`InstancedMesh`、几何合并）、LOD、按需渲染/离屏暂停、后处理降分辨率。**别说"感觉挺流畅的"。** |
| OPC UA 和 MQTT 什么关系？ | OPC UA 面向设备信息模型与可靠读写（地址空间、类型、订阅、可写节点），适合站内系统集成；MQTT 面向轻量高频上报与广域分发，适合上云与多系统订阅。真实项目常是站内 OPC UA、上行 MQTT。 |
| 时序数据存哪、采样频率多少？ | 诚实说 Demo 是 SQLite + 定时落库；真实方案按写入量与保留期选 TDengine/InfluxDB，并讲降采样与冷热分层。 |
| 点位数几千个怎么管？ | 从硬编码升级为**物模型 + 点位映射配置**（设备类型 → 测点模板 → 实例绑定），这是我最想先动手改的地方。 |
| 你在大团队里承担什么？ | 直接给 30/60/90：先接场景与数据绑定层 → 立性能与技术基线 → 独立负责一个站/模块的端到端交付。（见第 4 节） |

## 7. 诚实边界：这些别说满（说满了必被拆穿）

- ❌ "我做过完整的数字孪生平台" → ✅ "我独立打过一条从工业协议到 WebGL 的完整通路，平台化部分是我下一步要补的。"
- ❌ "我用 CAD/Revit 做过资产轻量化管线" → ✅ "我做过程序化建模与 glTF 加载通道，CAD 减面流水线是我希望补齐的。"
- ❌ "时序数据我们存了专业时序库" → ✅ Demo 用 SQLite，生产要换时序库（并说出选型理由）。
- ❌ 别把"仿真"说成"接了真实设备"：Demo 的遥测由后端仿真推流产生，OPC UA 服务端也是自建的。
- ⚠️ 两处文档不一致**已修正**（`public/models/` 与 "TypeScript" 已改）；`backend/tests/` 已补齐 **51 个用例**，可当场运行。
- ⚠️ 仍然**没有 CI、没有容器化、没有鉴权**（`.github/`、`Dockerfile` 均不存在）。主动说出来并给出补齐顺序，比被问出来强得多。
- ⚠️ 严格说它还不是数字孪生，而是停在**数字模型 → 数字影子之间**：数据源是仿真引擎（负荷需求是唯一随机源），没有真实物理实体，也没有状态估计器。**主动划清这条界线是加分项**，说满了才会掉档。
